# Frust - Review Focus

## Review Priorities

1. **Cross-thread + FFI correctness in the shells and render split.**
   `frust-shell-common::render_split`, and the sanctioned-unsafe zones in
   `frust-shell-android::jni_glue` / `frust-shell-ios::ffi_glue`, hand frame state across the
   render-thread boundary. A race near surface destroy/recreate is the costliest regression class
   in this codebase — weight any touch to these paths heavily regardless of diff size.
2. **Feature-flag matrix integrity.** `frust` carries `default = []` — the five design systems are
   ordinary sibling plugin crates (`frust-glyph`/`frust-material`/`frust-cupertino`/`frust-shadcn`/
   `frust-beui`), not a catalog feature to opt out of. Platform FFI deps are still target-gated, and
   a workspace-wide build still silently re-unifies any Cargo feature back on across every member —
   the remaining live risk is a *new* cargo feature reintroducing that hazard, not the design-system
   catalogs (which no longer have one). Check any new default-feature wiring against a
   package-scoped `cargo build -p <crate> --no-default-features`, not against `cargo build
   --workspace`.
3. **Version-pin and hand-sync discipline in manifests.** `wgpu` is a frust-owned pin (no `vello`
   constraint above it) — a bump still needs the full engine gate suite (device smokes across
   backends), not a casual `cargo update`. The `[profile.*]` blocks are hand-synced across five manifests (root
   `Cargo.toml`, `crates/frust-drive/templates/app/Cargo.toml.tmpl`, `examples/huddle/Cargo.toml`,
   `examples/glyph-catalog/Cargo.toml`, `examples/material3-demo/Cargo.toml`) — there is no single
   source of truth, only the tripwire test `cargo test -p frust-cli --test profile_sync`. Flag any
   manifest edit that touches one copy without the others.
4. **Plugin backend parity.** A new public API surface on the shared-preferences, secure-storage,
   or camera plugin must extend the shared cross-platform conformance suite, not land against a
   single platform backend. A one-sided addition is a parity gap, not a complete feature.
5. **Frame-gate/pacing semantics.** `frust-shell-common::frame_gate` decides whether a frame runs
   or skips; a wrong decision presents as a silent stuck UI or a battery regression, not a crash.
   Every gating seam must preserve its kill-switch env var revert path (e.g.
   `FRUST_NO_RENDER_THREAD`) — removing one is a regression even if the normal path still works.

## Known Hot Spots

| Area | Why fragile |
|------|-------------|
| `frust-shell-common::render_split` + `frust-render` surface/present handoff | The surface can be destroyed at any point in the Ack/barrier handoff; lifecycle edges (backgrounding, rotation, view recreation) are where deadlocks and races actually surface. |
| `frust-shell-common::frame_gate` + animation pacing | Skip decisions aren't recorded across the render-split channel, so skip-sensitive measurements need `FRUST_NO_RENDER_THREAD` to be trustworthy; a wrong skip looks like a hang, not a test failure. |
| `frust-shell-common::surface_mode` | Single-writer contract enforced only by a source-scan conformance test, not the type system. `ResolvedSurfaceMode::RefusedTranslucent` is a genuine platform fact (the surface's own compositor offered no translucent alpha mode), not a renderer degrade — the `frust-engine` render path itself never refuses a translucent surface. |
| Widget layout-skip handling (`frust-widgets`, design-system plugins) | Layout is skipped per pod (CORE_ARCHITECTURE Data Flow): a widget's `layout` result must be a function of its constraints, the context's global inputs and state that changes only through a dirtying channel (rebuild returning `LAYOUT`, paint `request_layout`/`request_frame`, a consumed event, `EventCtx::request_layout`). Any change to a container's child-conditional logic needs its skip path re-verified, not just the happy path. Review tools: `FRUST_LAYOUT_AUDIT` / `RenderRoot::set_layout_audit` (skipped vs forced pass, `layout-audit:` warnings; compares geometry only, so a stale colour or glyph is invisible to it), `crates/frust-widgets/tests/layout_skip_widgets.rs` and `plugins/*/tests/layout_skip_audit.rs` (a new widget gets a case in the matching harness). Five recurring plugin failure shapes: (1) anchor cells read in `layout` — store the laid value and compare it in rebuild and paint; (2) reduce-motion snaps in paint — report whether the snap moved (`Lane::snap` returns it) and signal on a move; (3) layout used as an animation retarget hook — the triggering prop or paint change must itself signal `LAYOUT`; (4) ink baked into a run shaped at layout time — a colour change returns `LAYOUT`; (5) `set_content` on a text run in rebuild — return `LAYOUT`. Animated-height widgets must also request layout on the frame the animation *lands* on: `advance` returns `false` on the pass that snaps onto target, so `if anim.advance(t) { request_layout() }` leaves geometry a hair short of rest (`button_group` measured ~2e-4px, enough to drop a word). Pattern: `paint` compares what `layout` last ran with against the live state and requests layout on any difference; hand-rolled steppers share the flaw. A test asserting "no relayout requested" across a transition can pin the bug in place. |
| `frust-widgets::nav` (`crates/frust-widgets/src/nav/`) | Just decomposed from a single ~8,700-line `navigator.rs` into six modules (2,044-line `navigator.rs` core plus `ambient.rs`/`options.rs`/`controller.rs`/`view.rs`/`edge_swipe.rs`, all private and re-exported through `navigator.rs`) — the split has no review track record yet, so weight a touch to any of the six as if to the old monolith. Three recurring fragile classes now map to named files: layout-skip in `NavigatorWidget`'s cached-child layout (`navigator.rs`), back-press arbitration and reach (`navigator.rs` + `controller.rs`), and interactive edge-swipe gesture/claim state (`edge_swipe.rs`). |
| Reactive tracking (`frust-reactive`, `TrackedScope` consumers) | An untracked read of a render-relevant signal is a silent wake hazard — the UI doesn't update until some unrelated write happens to wake it. New rebuild-path reads need explicit `TrackedScope` coverage, not just a passing host test. |
| `frust-native-widgets` (`plugins/native-widgets`) FFI surface and `present/` | JNI export symbol names and Kotlin package/class names are frozen once shipped; evolution must be additive only. There is exactly one generic factory/listener per arm — the Kotlin `FrustNativeControlFactory`/`FrustNativeListener` pair on Android, one Rust ObjC target class (`FrustNativeControlTarget`, which also carries the tab bar's `UITabBarDelegate`) on iOS, the Rust AppKit `DesktopViewFactory` + target in `src/appkit/` on macOS — so a new per-control glue path or second target class is an architectural regression, not a convenience. `present/` holds one process-wide Busy slot, a generation-tagged live entry and an exactly-once outcome shared by alerts and sheets: a callback that can resolve a presentation other than its own generation, a path that frees the slot twice or never, or a change to the `LivePresentation::dismiss(then)` continuation seam (a displaced presentation must run its successor exactly once) breaks the one-outcome contract every caller awaits on. App chrome (`chrome/`, `api/scaffold.rs`, `apple/chrome.rs`, `android/chrome.rs`) adds a fourth frozen Kotlin class, `FrustNativeChrome`, whose two exports (`nativeOnChromeEvent`, `nativeOnChromeLost`), `FIELD_*`/`INSTALL_*`/`ICON_SLOT_*` codes and `CHROME_MENU_STRIDE`/reselect shift are pinned by `tests/kotlin_conformance.rs` — change them additively or not at all. There is one `native_scaffold` per app (a second must publish nothing); the chrome slot's generation guard must drop stale reports. iOS containment: the one `FrustViewController` lives in exactly one page at a time and its `FrustView` stays at origin zero inside its host view (Mode B wrappers assume it), moved only through the remove-then-add turn — a child controller's view under another controller's view aborts the process. On Android the `FrustSurfaceView`'s root must never be re-parented (it fires `surfaceDestroyed` inside a frame); bars are siblings and the root is padded. The shell's JNI grew `nativeOverlay*` (`nativeOverlayMode`/`nativeOverlaySurfaceChanged`/`nativeOverlaySurfaceDestroyed`), which is not under this plugin's symbol freeze; the two additive JSON ops (`overlay`, `disposeOverlay`) now are part of the frozen wire. |
| Overlay present pairing (`frust-shell-common::overlay` `OverlayTable`, `frust-shell-android` `OverlayLedger`, `frust-render::overlay`, `SurfaceRenderer::*_segmented*`) | A frame is one compile and one submit: main and overlay segments must come from the same `encode_segmented`, and the presents run main-first from the one `SegmentedPresents`. The ledger must pair each cut range with the frame id the render thread actually draws (16 frames kept); a range paired with a different frame draws unrelated commands onto the overlay, and an empty range must mean draw nothing. Overlay surfaces must drop before their layer or window is handed back, and a knob-off frame must stay byte-identical. A withdraw never waits (the hand-back is deferred to the land that drops the surface), and the overlay lock is never held across an acquire or a present: a regression there stalls the UI thread for an acquire timeout. On iOS (`frust-shell-ios` `ffi_glue`, `FrustOverlayView`) one parked frame id carries main plus every overlay and the UI thread presents them inside one `CATransaction`, present before poll: a withdrawn overlay's parked present must be dropped before its surface, and nothing may acquire or configure a surface while a frame is parked (the handoff waits up to 50 ms, then drops the parked frame). A late Android present into an abandoned window fails rather than frees (`android-overlay-withdraw-after-return`); the knob stays default-off (`android-overlays-opt-in-pending-device-leg`). |
| Texture import lifetimes (`frust-render::texture_bus`, `frust-render::native_import`, `frust-gpu::import`) | A native frame's `release` is the producer's licence to reuse its buffer, so it must run only after the imported texture is retired and the retirement fence fired (the registration-drop path chains a second fence), never when the importer returns; the importer must take its own buffer reference. `MAX_RETIRING` refusal must release the newest frame at once and keep the last good one shown, and a frame for a kind with no importer must be refused, not leaked. A change that releases earlier shows as producer-side tearing or reuse corruption, not a crash. |
| `frust-drive` cores + `frust-mcp` + `frust-dap` | Print-free contract, one family, three tripwires (`crates/{frust-drive,frust-mcp,frust-dap}/tests/print_free_cores.rs`): all three link into `frust-tui`, so a stray `print!`/`println!` garbles the workbench's raw-mode terminal — `frust-dap`'s is the strictest, zero-allowlist, since it is *embedded-only* (no `frust dap` process, no stdout of its own to fall back on at all) and its host owns the terminal outright. All process spawns must pipe stdout/stderr, never inherit. |
| `frust-widgets` authoring boundary | Baseline widgets must never depend on a design-system plugin (`frust-glyph`/`frust-material`/`frust-cupertino`/`frust-shadcn`/`frust-beui`); all container plumbing goes through the authoring module. Structurally enforced now (the five are separate crates depending only on `frust`, so `frust-widgets` cannot name them without a manifest edit) — a manifest change adding one as a `frust-widgets` dependency is itself the violation to flag, since no source-scan test remains to catch it after the fact. |
| Theme resolution (`frust-theme` / `Theme` recovery) | Precedence is explicit builder value > theme token > unthemed fallback. A hardcoded metric or color where a token already exists is a defect. `frust-core`/`frust-widgets` must never call `Instant::now()` directly — time enters only as shell-supplied `FrameTime`. |
| `frust-database`'s turso bridge (`plugins/database/src/turso.rs`) | The tier's first plugin-owned OS thread + tokio runtime; a caller-thread `block_on` would panic under `panic="abort"`, so the bridge sends futures across a channel instead. The `AsyncContext` guard is a provable-subset detector (`try_current`+`try_id`), not exhaustive — a change to how it's computed can silently widen or narrow what it catches without any test failing outside the two cases already pinned. |
| `plugins/material`'s newest, densest surfaces (`button/`, `slider/`, `carousel/`, `date_picker/`, `time_picker/`, plus Phase 4's nav tier: `appbar/`, `toolbar.rs`, `split_button.rs`, the liquid-indicator family in `navbar.rs`/`navigation_rail.rs`/`navigation_drawer.rs`) | The button family shares one press-morph driver (`RadiusPaddingMotion`) across every variant plus a native gradient-decoration seam and three overflow strategies; the slider owns its own frame-clock haptic scheduler and wavy-phase paint math. Phase 3 added `carousel/`'s weighted-slot layout solver + snap-physics drag machine and the pickers' in-crate calendar/dial geometry math (an `atan2` `(0,0)` NaN trap). Phase 4 added the nav tier: `toolbar.rs`'s scroll-hide visibility controller + FAB 80→56 morph choreography (icon-centering degrade tracked in `docs/LIMITATIONS.md` `material-fab-fixed-tier-icon-centering`), `split_button.rs`'s two focus-separated child pods routing input independently, and the two-spring liquid selection indicator `navbar.rs` establishes and `navigation_rail.rs`/`navigation_drawer.rs` both cite. None of it has a regression history yet — weight a touch to any of it heavily until one builds up. |
| `frust-material`/`frust-shadcn`/`frust-beui` overlay `modal`/`anchored` hosts — staged vs. unstaged dismiss routes | Every host-chrome dismiss gesture (scrim tap, Escape, close button, drag, and — material only — Android back) stages a reverse-ramp exit before firing the app's dismissal; a panel's own content-owned close control that pops via `NavigatorController::pop()` directly instead dismisses **unstaged**, with no ramp; material content reaches the staged route through the `ModalDismiss` handle (`.dismiss_handle(..)`), and its `search`/`navigation_drawer` are the two known holdouts still popping directly (`docs/LIMITATIONS.md` `material-modal-staged-dismiss-private-to-host`). `frust-beui::overlay::modal`'s pair is shaped differently: `ModalView::on_dismiss` is an event-pass dismiss-requested report that fires *alongside* the staged exit, not instead of it (`request_dismiss` reports, then stages), and `ModalView::on_close` fires once the exit settles — both run for one chrome dismissal, and staging is governed by whether an `on_close` is installed. Its `show_modal` route (`push_with_options` + `StagedPop`) installs no content-side dismiss forwarding at all, so a beUI content-owned close reaches only a bare `NavigatorController::pop()`; it has not had the forwarding-seam audit material had — treat a beUI content-owned close the same way until one runs. The recurring shape to watch for: a new modal-family component wiring its own in-content close affordance down the unstaged path while the rest of the same panel stages — easy to get right for chrome, easy to miss for content. Two more recurring shapes the Phase-3 closure round caught in both hosts: (a) any leg that ramps the surface back **open** (a refused staged pop, a caught mid-exit drag) must itself clear the exit-staging flag — leaving it set across a reopening leg permanently locks the surface out of ever dismissing again; (b) a barrier must gate its input swallow on `progress > epsilon`, never on open/closed state alone — an invisible surface (progress ~0, still mounted) that keeps absorbing input is the same defect class regardless of which host it's in. |
| Scroll physics + arbitration (`frust-widgets`' `scroll_core.rs`/`scroll.rs`/`list_view.rs`/`viewport.rs`/`physics/`) | `ScrollView`, `ListView` and the sliver viewport run on one `ScrollSurfaceCore` plus the `ScrollSurface` trait in `scroll_core.rs`, which owns the path-dependent drag accumulator, edge pull, claim/veto takeover (`SCROLL_CLAIM`/`InnerScrollState`), fling/settle/ballistic, controller drain and the `on_scroll` owed-notification rule. Review the owner-supplied position methods (`pixels`, `displacement`, `set_allowed_position`, `decay_displacement`, `settle_to_edge`, base offset): `ScrollWidget`'s out-of-range offset and `ListViewWidget`'s clamped offset plus `overscroll` must each keep their own float arithmetic, and a new surface implements the trait rather than copying the machinery (note the `#[cfg(test)]` `Deref` shims on both widgets). `RubberBand` is feel-pinned (byte-for-bit legacy math); any edit to it or to a platform-parity physics needs its own pinned test, not just a passing suite. The paint-only rule at the core's `stretch_transform` (no layout read of `edge_pull`/intensity) is load-bearing for the frame-gate — a regression there reads as a subtle layout/paint order bug, not a crash. |
| `frust-engine::renderer`'s frame recording (`crates/frust-engine/src/renderer.rs`) | `EngineRenderer::encode` records a whole frame's rounds — opening (clear + opaque class runs + the first drawing surface round in one pass; page/filter rounds run ahead of it) → per-round pass → punch pass — into a caller-owned `wgpu::CommandEncoder` it never submits, with two sanctioned exceptions, both strictly ahead of the scene pass: growing the image atlas submits its own copy-only maintenance command buffer ahead of the frame's writes, and a glyph atlas with pending work gets its dirty pages replayed on their own encoder (one submit per dirty page) before the scene pass records. An `EngineError` anywhere in that walk must leave the encoder exactly as found, or a half-recorded pass reaching the caller's `submit` corrupts whatever else that encoder had queued. A pass now sets a pipeline per class run: class runs must tile each segment in painter order, every strip pipeline must name the explicit strip layout (the bindings test pins it to the Uber program's derived layout), and an image's class comes from its lowered record, not its flag. Any touch to round order or the punch pass needs the "records everything, submits nothing but the atlas-growth and glyph-replay exceptions" invariant re-verified, not just the happy path. |
| Image residency / atlas (`frust-engine::cache::images` + `gpu::atlas`) | Residency is committed only once a frame's pending eviction/upload plan is actually serviced (`ImageResidency::acknowledge_plan`) — a frame refused after compiling must re-offer the identical plan on the next one, not drop it, or an atlas rectangle ends up recorded resident with texels nothing ever wrote. The tier budget clamps (`choose_tier` → `AtlasBudget::for_choice`) and the aspect-preserving minify-to-fit path are the other place a regression reads as a rendered-wrong image, not a crash. |
| The scheduler (`frust-engine::schedule`) | Bounds a frame to `MAX_LIVE_PAGES` (3) live intermediate pages: a two-slot ping-pong allocator keyed on layer-depth parity plus one bounded spill page (`PageParity::Spill`) a regular layer falls back to instead of escalating. A shape past that bound (a fourth live page at once, a chain past `MAX_CHAIN_DEPTH`) is refused rather than rendered wrong. On the engine tier a refusal is a skipped frame with no fallback renderer, so a scheduling regression here presents as a frozen surface, not a wrong pixel — weight any touch to the parity/allocator/spill logic accordingly; the spill's own "bounded at one" invariant (a second concurrent spill request is refused exactly like before) is the newest and least-exercised part of this path. Retained pages live outside `MAX_LIVE_PAGES` (the store owns them, the scheduler's groups and spill page are untouched by a retained round), so a change that routes a retained page through the pool, or counts one as live, breaks the bound from the other side. |
| Retained store + ledger contract (`frust-engine::cache::retained`, `compile::layers`/`open_retained`, `frust-render` ledger plumbing, `frust-widgets::repaint_boundary`) | Four parties must agree: the compiler marks a body unretainable (mask or path clip, punch, external texture, shader quad, `BackdropBlur`, stray pop, not wholly inside viewport and scissors — path clips are always masks, never retained), the store refuses a body or a `DrawRetained` it cannot serve (`RetainedKeyMissing` refuses the frame and clears the store), the shell publishes the ledger after submit (an empty one at destroy) and repaints without pages after a refusal, and the widget draws a page only when the ledger holds its (key, extent, scale) and covers the paint serial the page was recorded under (a dropped scene must never let an older page pass as the latest recording). Re-recording a key must evict a page the new recording does not reach (refused, nested or unrendered body), and a hover-link change or focus-epoch advance must re-record every boundary once. A page drawn from a stale or wrong-scale entry is a visibly wrong frame; the store and ledger must be invalidated on surface recreate. Pages at rest paint plain by design — a change that records every page every frame defeats the cost model. |
| Backdrop blur round split (`Schedule::build_frame`, `RegionCopy`, `FramePass::Copy`) | The surface round is cut at each backdrop, the region is copied into a pooled page (by `RegionCopyMode`; pooled pages lack `COPY_DST`, so a `Texture` copy goes through the engine staging texture), blurred by the shared `pass_rounds`, then drawn in the next root round; the opaque pass must stop at the first backdrop or it paints over content the copy has to read. A backdrop inside an isolated layer, retained body or suppressed layer is dropped, not blurred wrong; more than 4 per frame refuses the frame. |
| Alpha polarity + surface-path selection (`frust-render::context`'s `choose_engine_render_path`, `frust-gpu::surface`'s `compositor_expects_premultiplied`) | Which of {engine-direct, engine-direct-unpremultiply} a surface takes is decided once at configure time from (backend, alpha mode) — the only per-frame deviation is the root-via-intermediate for a direct-arm frame carrying a `BackdropBlur` (`frame_renders_via_intermediate`; the swapchain stays `RENDER_ATTACHMENT`-only and must never be widened, and a knob-off, backdrop-free frame must keep its single-target shape) — get it wrong and a surface silently double-corrects or under-corrects alpha, which reads as a color/translucency bug on one platform only and is easy to miss on any other. `compositor_expects_premultiplied` is a one-backend-one-mode carve-out for an upstream wgpu-hal misreport (Metal's `PostMultiplied`, `docs/LIMITATIONS.md`'s `engine-metal-postmultiplied-truth-bug`) found only by device testing — treat any new backend/mode combination as needing the same device-level scrutiny, not just a read of the wgpu docs. |
| `frust-gpu` device/surface foundation (`context.rs`/`surface.rs`/`lifecycle.rs`/`pipeline_cache.rs`) | Just absorbed `frust-render`'s own `RenderContext`/`SurfaceFactory`/lifecycle/pipeline-cache code in the p8-05 move — one copy now shared by every consumer of the crate, re-exported name-for-name so shells see no change, but the merge itself has no review track record yet. Weight a touch to any of these files as if to the pre-merge originals; a re-export drifting from the name it replaced is a break every shell would hit silently at compile time only if the type itself changed shape. |
| `frust-core`'s overlay portal (`overlay.rs` + `RenderRoot`'s routing) and the pass-scoped clipboard slots | A floated surface is a per-paint *registration*, not a retained tree: the root clears the registry every paint, hit-tests the registered rects band-first (`Tooltip` above `Floating`) **before** the main tree, and delivers a hit as an `InputEvent::Overlay` broadcast that only the owner holding the matching `OverlayKey` acts on — so the owner, never the root, holds the pod and forwards its capture and focus. Four invariants to re-verify on any touch: a `Down` routed into an overlay never blurs the main tree's focus session; an `OverlayInput::Transparent` entry is skipped by the routing pre-pass outright (no input at all, not even an `OutsideDown`); an owner that stops painting loses its entry on the next paint (a kept-mounted exit ramp *is* "keep registering"); and a focus link stamped with an older session must never seed or authorise anything, since that stamp is the only thing stranding a link no container can reach to clear. `OutsideTap::Notify { consume }` decides whether the dismissing press also reaches the main tree — the wrong answer either eats a press the app owed a button or activates that button while dismissing. Hover-opened surfaces run their open/close delays off the paint clock (`PaintCtx::frame_time`), so a skipped frame is a skipped timer, and the pass's one-shot clipboard write / paste-request slots are drained once per frame by the shell — a second write in one pass replaces the first rather than queueing. |
| `GpuStrip`/`GpuEncodedPaint`/`GpuConfig` layouts (`frust-engine::gpu`) | Byte-compatible by design with the sparse-strip reference renderer's own layouts — a field reorder, size change, or padding drift here does not fail to compile, it silently reads the wrong bytes on the GPU side. Any touch to these types (or the WGSL structs in `crates/frust-engine/shaders/` that read them) needs the golden/oracle suite re-run, not just a host unit test. Paint type 6 (`PaintType::Glyph`) is valid only with `RECT_STRIP_FLAG`, a glyph-quad draw may own an empty strip range, and the `glyph_quads` side table must stay in depth step with the draws. |
| The parallel strip walk (`frust-engine::compile::parallel`) and the resident glyph-run cache (`frust-engine::text::atlas_policy`) | Both are byte-identity contracts, not features. `plan()` mirrors the walk's bracket handling (exhaustive matches: a new `Command` variant fails to compile until it has a planning decision) and the walk takes a helper's run only with no mask open and a bit-identical transform — a wrong decision costs work, never a pixel, so a regression here reads as a *performance* loss the goldens cannot see: any touch re-runs `parallel_walk` and the goldens under `FRUST_ENGINE_PARALLEL_MIN_COST=0` and `FRUST_ENGINE_NO_PARALLEL=1`. The resident-run path restates `glifo` 0.3.0's placement arithmetic and keys on face / size / hinting / glyph ids (never colour or translation); a `glifo` bump or a key change re-runs `glyph_run_cache` and the GPU byte-identity suites. The bulk touch ahead of the evicting `maintain` also probes every subpixel sibling of each glyph position drawn within the age window: a change that stops keeping the siblings brings the S1 replays back (`replays` / `glyph_misses` / `replay_us` on the enc line), never a wrong pixel. `FRUST_ENGINE_NO_PARALLEL`, `FRUST_ENGINE_NO_GLYPH_RUN_CACHE` and `FRUST_ENGINE_NO_GLYPH_QUADS` are the revert paths — removing one is a Major. |
| Staging ring and page bind-group cache (`frust-gpu::staging`, `frust-engine::renderer`'s upload path, `gpu::bindings::SourceGroupCache`) | A slot may be handed out only while `Ready`, and its re-map must ride the caller's own encoder (`map_buffer_on_submit`), so the caller's submit is the fence: a ring that reuses a slot still in flight, or a copy recorded after the pass that reads it, corrupts uploads only on the frame that overlaps, which a single-frame test never sees. A refusal (`staging_busy`, `staging_too_large`) must fall back to queue writes with the same bytes, and both routes must stay pixel-identical (`set_staging_ring` A/B in one process). A cached bind group keeps its texture alive: every path that drops or recreates pages or the coverage view (surface-format change, `resize`, `clear_retained`, `set_retained_budget`) must clear the cache, and the per-frame sweep must drop what the frame did not use. `FRUST_ENGINE_NO_STAGING_RING` is the revert path. |
| Thread classes, ADPF and the Android frame sync (`frust-reactive::thread_policy`, `frust-shell-android::adpf`, `ffi_support::FrameSyncLatch`) | The policy may only lower a thread or keep a better inherited priority: writing a weaker value over the render thread's inherited one, lowering an async worker, or capping the blocking pool (it carries parked plugin calls beside decode) is a regression, and the `sys` shim's `unsafe` must stay calling-thread-only. ADPF is opt-in (`FRUST_ADPF`), one session per process, closed on pause and surface destroy, and a missing `dlsym` symbol must leave it off. The `FrustSurfaceView` JNI surface is frozen and additive: 26 exports stamped by `android_app!` (`crates/frust-shell-android/src/lib.rs`, `nativeFrameSync` and `nativePerfTrace` the newest) plus seven defined in `jni_glue` (`nativeInitPlatform`, `nativeEditCommand`, `nativeTakeClipboardWrite`, `nativeTakePasteRequest`, `nativeOverlayMode`, `nativeOverlaySurfaceChanged`, `nativeOverlaySurfaceDestroyed`). A gated poll must never lose a one-shot clipboard edge (the latch holds it until the matching `nativeTake*` call), a baseline Kotlin reads outside a sync must be recorded, and the platform-view poll stays ungated. `FRUST_NO_THREAD_TUNING` and `FRUST_NO_FRAME_SYNC` are the revert paths. |
| First-frame warm-up and Android pipeline-cache persistence (`frust-render`'s `FirstFrameWarmUp`, `frust-engine`'s `warm_up_list`, `frust-shell-android`'s `CachePersistence`) | The strategy is applied once per surface install inside the first encode and must encode and submit nothing of its own; `steal` stays the default (`await`/`finish` make the first frame pay the whole list and widen the 2 s surface-destroy barrier window). The list's order is a measured contract — the first frame's programs first, the surface `LayerComposite` last — pinned by a device-free order-and-membership test. Persistence must never block a frame or a lifecycle barrier, never land an older blob over a newer one (the generation ticket is taken on the reading thread), and record the file's bytes only after a successful write; `pipeline_cache_data` must stay readable between a surface's destroy and the next install. |
| `frust-text`'s font oracle (`src/oracle/`) | The only `unsafe` in the text tier: check a `// SAFETY:` note on every block, no `unsafe` token outside `{apple,android,fontconfig,dwrite,store}.rs` (the guard tests in `oracle/mod.rs` must stay), and `Send` wrappers/COM guards that match the real thread and release rules. Hidden (dot-prefixed) and `hvgl` faces must be flagged, never swapped for a sibling face; the persistent cache is version-stamped and must reject stale or corrupt entries rather than serve a wrong face |

## Severity Calibration

- **Critical:** on-device visual or input regressions — device gates are the arbiter here, a green
  host-side run does not clear a device-gated change. A casual `wgpu` bump made without the engine
  gate suite. A renamed or removed frozen FFI symbol (or `FrustNativeChrome` member) in `native-widgets`; re-parenting the Android frust root or breaking the iOS containment invariant.
  Data loss in the shared-preferences or secure-storage plugin. Any blocking or parking call on the
  platform UI thread (typed fail-fast + `spawn_blocking` is the contract). A `render_split`
  deadlock.
- **Major:** a feature-gating regression only catchable by a package-scoped
  `--no-default-features` build, not by the normal workspace build. Removing or bypassing a
  kill-switch seam. Weakening a source-scan conformance test (`print_free_cores`, `profile_sync`,
  `surface_mode`'s single-writer check) instead of fixing the underlying violation. A `frust-widgets`
  manifest edit adding a dependency on any of the five design-system plugin crates. Target-gated
  code that no longer compiles under the Android or iOS compile gate.
- **Minor:** style/naming nits. Doc drift that's still within its budget. A gap covered only by a
  host-side test where a device gate already exists for the same behavior.

## Out of Scope

- Benchmark median deltas without tail data — in this project the tails carry the regression
  signal; a median-only perf claim is not a finding.
- The `clean-signals`/`clean-signals-frust` strings and the identical `clean-signals` registry
  requirement at its three consumer sites — load-bearing, not typos to "fix".
- Any nested working-notes repository checked out beside the sources — not part of this build; out of scope entirely.
- Generated Android/iOS project trees under `examples/*` — scaffold output. Review the templates
  in `frust-drive` instead of the generated artifacts.
- Anything already entered in `docs/LIMITATIONS.md` — accepted, measured degrades. Do not re-flag
  them; cite the id if a change is adjacent to one.
