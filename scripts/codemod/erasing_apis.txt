# Erasing-API name list for scripts/codemod/frust_any_codemod.py.
#
# One entry per whitespace-separated word, grouped under a [section] header;
# `#` starts a comment. Extend a section when a later change widens another
# API — the tool needs no code change.
#
# Entry spellings:
#   .name        a method call `recv.name(..)`
#   name         a free-fn call `name(..)`, bare or module-qualified
#                (`frust_shadcn::card(..)`); a `Type::name(..)` call never
#                matches a free-fn entry
#   Type::name   an associated-fn call `Type::name(..)` (optionally
#                path-qualified in front of `Type`), e.g. `Route::new`,
#                `ListView::builder`
#
# [slot]    (T1) single-view `impl View<State>` / `V: View<State>` and
#           `Option<V>` parameters. T1 fires only when an argument is a bare
#           erasure call — `any(X)`, `frust..::any(X)`, `AnyView::new(X)` — or
#           `Some(<erasure call>)`; it then drops the erasure. Any other
#           argument, including a `vec![..]` list, is never touched, so a name
#           that is a single slot in one crate and a list in another (`card`,
#           `drawer`, `message`, `side_sheet`, `.leading`, `.trailing`) is safe
#           here: the list form simply never matches. The argument position is
#           not checked, which is sound because no listed API takes a
#           non-generic `AnyView<State>` parameter (verified against the
#           signatures at the time of writing; re-check when adding a name).
# [builder] (T4) builder-closure parameters `impl Fn(..) -> V`: a closure
#           argument whose body is exactly one erasure call (optionally in a
#           `{ }` block) loses the erasure.
# [exclude] path suffixes of same-named APIs whose closure or slot is NOT
#           generic, matched against the call's qualifier or, for an
#           unqualified call, against the `use` that imports it.
# [list]    (T5, opt-in `--t5` only) list parameters (`Vec<V>`,
#           `impl IntoIterator<Item = impl View<State>>`). Without `--t5` the
#           tool never rewrites them. With it, a `vec![any(E1), .., any(En)]`
#           whole argument loses every erasure when all E_i share one head
#           (callee path + trailing method names); `Column`/`Row`/`Stack` and
#           `.children` are list callees even when absent here. A same-head
#           list can still be mixed-type (a generic callee), which then fails
#           to compile, and the apply recipe restores `any()` on that list.
#
# Derived from the merged signatures of crates/frust-widgets, crates/frust,
# crates/frust-core and plugins/{material,glyph,cupertino,beui,shadcn}.
# Deliberately absent: `breadcrumb_item` (returns its argument's type `V`, so
# dropping the erasure would change the result type), `.children` (a list —
# see [list]), and `.ghost` (a closure — see [builder]).
